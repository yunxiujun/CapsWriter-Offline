# LLM 本地知识库使用说明

## 功能是什么

每个 LLM 角色都可以有一个互相隔离的本地知识库。知识库默认关闭，开启后只读取该角色文件夹中的 `.txt`、`.md`、`.markdown` 文件，不读取图片、网页、选中文字或剪贴板。

默认目录规则：

```text
CapsWriter-Offline\LLM知识库\角色主名称
```

例如角色配置为 `name = '知识库助理 | 资料助理'`，它使用的默认文件夹就是 `LLM知识库\知识库助理`。只使用竖线前面的第一个名称作为文件夹名。

## 开启普通角色的知识库

打开对应的 `LLM\角色名.py`，把：

```python
enable_knowledge_base = False
```

改成：

```python
enable_knowledge_base = True
```

保存后角色会自动重新加载。第一次调用该角色时会自动创建同名文件夹，把资料放进去后再次调用即可。关闭时改回 `False`；关闭状态不会扫描目录。

## 使用知识库助理

1. 把资料放入 `LLM知识库\知识库助理`。
2. 可以继续建立子文件夹，程序会递归读取。
3. 说“知识库助理，你的问题”或“资料助理，你的问题”。

资料不足时，助理应回答“知识库中没有找到相关信息”，不会主动联网补充。

## 可选设置

```python
enable_knowledge_base = False       # 总开关，默认关闭
knowledge_base_folder = ''          # 留空使用同名文件夹，也可填写绝对路径
knowledge_base_top_k = 8            # 大型知识库最多检索多少个片段
knowledge_base_max_chars = 50000    # 单次最多发送多少知识库字符
knowledge_base_evidence_max_chars = 12000  # 回答后最多附加多少原文字符
knowledge_base_evidence_top_k = 2     # 回答后最多附加多少个相关原文段落
knowledge_base_evidence_score_ratio = 0.80  # 候选段落相对最高分的最低比例
```

自定义绝对路径示例：

```python
knowledge_base_folder = r'D:\我的资料\公司制度'
```

## 检索规则

- 小型知识库：在字符上限内向模型提供全部资料，避免遗漏。
- 大型知识库：把文件分段，只提供和问题最相关的片段。
- 文件修改后自动刷新缓存，不需要重启。
- 单个文件默认最大 2 MiB，超出时跳过并写入日志。
- 支持 UTF-8、UTF-8 BOM 和 GB18030 编码。
- 每段资料标注来源文件名，方便复核。
- 模型回答后，CapsWriter 会直接附加命中的完整相关段落；这部分由本地程序读取，不经过模型改写。
- `evidence_top_k` 是上限，不会强制凑满。第一名明显领先时只附加一段；候选分数接近时最多附加两段，并按相关度从高到低排列。

## 隐私与限制

`LLM知识库` 已加入 `.gitignore`，正常提交和制作 Release 时不会上传其中的私人资料。

知识库检索在本地完成，但检索出的相关文字仍会发送给该角色配置的 LLM API。不要把不允许发送给模型供应商的机密资料放入知识库。

本功能通过隔离上下文和严格系统提示词约束回答来源。LLM 仍是生成式模型，重要结论应根据回答中标注的来源文件复核。
